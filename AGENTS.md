# gtube

Repository-specific decisions; packaging and release rules follow `/code/pacman/RELEASE_POLICY.md`, with build details in `RELEASES.md`.

## Windows builds are unsigned

The Windows executable ships without a code signature, so Microsoft Defender SmartScreen warns on first run and users click "More info", then "Run anyway"; the README does not mention it. This matches Streamlink, which also ships unsigned Windows builds. Signing was declined for now: SignPath's free certificate needs a manual approval for every release, which breaks release automation, and Azure Artifact Signing costs about $10 a month. If Windows users become a real audience, Azure Artifact Signing is the option that keeps releases automatic: it signs inside `publish.yml`, before checksums and attestation.

## Test builds update themselves; releases do not

gtube has two ways out. GitHub Releases are for anyone and carry no updater: a release build has no build name, so it never looks for updates. Test builds are for friends testing with the author: `tools/publish-update` builds the current commit for Windows, names the build after it, and publishes it to the update server at `http://updates.waka.mx/gtube/` (on the Hetzner machine), where a test copy whose user said yes fetches it within a minute. A test build asks once, on its first run, and does not look until the answer is yes; its title and corner say it is a test build, with its commit, and u turns updating off and on. It restarts into a new build only when nothing plays, no search or sign-in is open and gtube has been left alone for two minutes, at most once every 15 minutes unless the corner's "click to restart" is clicked; it comes back with the playing song where it was, without taking the keyboard, and says once that it was updated. A build that keeps failing on start goes back to the one before (gesso's gs_update). First installs come from `http://updates.waka.mx/gtube/`, whose page says all this, with `gtube-test-windows.zip`; public READMEs link releases only. Agents run `tools/publish-update` themselves after each commit worth testing, without asking, as on the other apps built on gesso; it refuses a tree with uncommitted changes. The signing key is `~/.config/gtube/update-signing.key` on the author's machine and never goes into the repository or CI.
